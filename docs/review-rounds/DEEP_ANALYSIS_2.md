# 🔬 کاوش ریزبینانه لوپ‌های سنگین — دور دوم

## ۵ لوپ بحرانی بررسی‌شده

### لوپ ۱: AacTranscoder — حلقه رمزگذاری AAC
**ایرادهای یافت‌شده:**

| ID | شدت | توضیح |
|----|------|-------|
| AAC-1 | 🔴 بحرانی | وقتی `encoder.dequeueInputBuffer(TIMEOUT_US)` برمی‌گردد به `< 0` (هیچ بوفری آزاد نیست)، PCM داده‌شده در `pcmBuf` **دور ریخته می‌شود** — هیچ مکانیزم بازآزمایی وجود ندارد. در فایل‌های صوتی بزرگ، این باعث گلیچ و خرابی صدا می‌شود. |
| AAC-2 | 🟡 عملکردی | `lastPts` مقداردهی اولیه `-1L` — در فریم اول، شرط `if (pts <= lastPts)` همیشه درست است چون هر PTS ≥ 0 > -1 است، پس PTS فریم اول به `0 + 1000 = 1000` جابجا می‌شود. |
| AAC-3 | 🟠 زیبایی | حلقه دکودر با `timeout = 0` (non-blocking) اجرا می‌شود ولی حلقه اینپوت با `TIMEOUT_US = 10ms` — این تقارن نادرست است و می‌تواند باعث شود دکودر بوفری نداشته باشد ولی اینپوت دائماً صف‌شده باشد. |
| AAC-4 | 🔵 کیفیت | `durationUs = trimEndUs - trimStartUs` — وقتی هر دو صفر باشند (بدون تریم)، `durationUs = 0` و پراگرس هیچ‌وقت گزارش نمی‌شود. باید از `MediaInfo.durationMs` استفاده شود. |

### لوپ ۲: MediaCodecTranscoder videoPass — حلقه رمزگذاری ویدیو
**ایرادهای یافت‌شده:**

| ID | شدت | توضیح |
|----|------|-------|
| VID-1 | 🔴 بحرانی | `var muxer: MediaMuxer? = null` و سپس در `try` مقداردهی می‌شود ولی بلوک `try` ایندنت نادرست دارد — `muxer` به‌عنوان `var` لوکال در scope داخلی تعریف نشده و بلوک `finally` به `muxer` از scope بیرونی دسترسی دارد. اگر `muxer = ...` خطا بدهد، `finally` روی `null` اجرا می‌شود. |
| VID-2 | 🟡 عملکردی | `muxer?.stop()` در `finally` بیرونی فقط اگر `muxerStarted == true` فراخوانی شود، ولی اگر `muxer.start()` اجرا شده و سپس خطا رخ دهد، `muxer.stop()` و `muxer.release()` باید هر دو فراخوانی شوند. |
| VID-3 | 🟡 عملکردی | حلقه فریم‌ریت: `val keepAllFrames = settings.frameRate == null` — اگر فریم‌ریت null باشد (یعنی فریم‌ریت اصلی حفظ شود)، `keepAllFrames = true` درست است. ولی وقتی frameRate ست شده، `frameIntervalUs = 1_000_000L / targetFps` — تقسیم صحیح می‌تواند برای fps=24 باعث فاصله 41666us شود که دقیق نیست (41666.67). |
| VID-4 | 🟠 زیبایی | بلوک `try` داخلی در `videoPass` ایندنت ناهموار دارد — آکولاد باز `{` بعد از `var muxer: MediaMuxer? = null` در همان خط `try` است. |

### لوپ ۳: AudioCompressor encodeMp3 — حلقه رمزگذاری MP3
**ایرادهای یافت‌شده:**

| ID | شدت | توضیح |
|----|------|-------|
| MP3-1 | 🟡 عملکردی | `var lastPts = -1L` — مثل AAC، در فریم اول باعث جابجایی می‌شود. |
| MP3-2 | 🟡 عملکردی | `findTrack` لوکال تعریف شده و از `MediaUtil` استفاده نمی‌کند — نقض DRY. |
| MP3-3 | 🔵 کیفیت | حلقه `while (remaining > 0)` برای فید کردن PCM به LAME از `buf.get(pcmOut, 0, chunk)` استفاده می‌کند، ولی `buf` قبلاً `position` و `limit` ست شده — باید مطمئن شویم `buf.remaining() >= chunk`. |

### لوپ ۴: WaveformSampler — حلقه نمونه‌برداری فرم‌موج
**ایرادهای یافت‌شده:**

| ID | شدت | توضیح |
|----|------|-------|
| WAV-1 | 🔴 بحرانی | حلقه PCM داخلی `while (i < n)` در هر دو شاخه pcm!pcmFloat و pcmShort، **بوفردکی** `buf` رو پیش می‌برد ولی **هرگز `buf` رو ریست نمی‌کند** — اگر دو بوفرد دکودر پیاپی داشته باشیم، موقعیت بوففر اشتباه می‌شود چون `buf.position()` از بوففر قبلی باقی مانده. |
| WAV-2 | 🟡 عملکردی | `extractor.advance()` بعد از فراخوان `queueInputBuffer(inIdx, 0, 0, 0, EOS)` اجرا می‌شود — وقتی EOS صف‌شده، `advance()` اکستراکتور رو جابجا می‌کند ولی داده‌ای برای خواندن نیست. بی‌ضرر است ولی ناکارآمد. |
| WAV-3 | 🟡 عملکردی | وقتی `extractor.sampleTime > MAX_PREVIEW_US`، EOS صف‌شده ولی `extractor.advance()` هم فراخوان می‌شود — بعد از advance، ممکن است نمونه بعدی هم در محدوده باشد ولی از قلم افتاده. |
| WAV-4 | 🔵 کیفیت | `peaks.max()` در اندروید API پایین از `FloatArray` مستقیم کار نمی‌.کند — باید از `peaks.maxOrNull()` استفاده شود (با فال‌بک). |

### لوپ ۵: MediaCodecTranscoder mergePass — حلقه ادغام ویدیو+صدا
**ایرادهای یافت‌شده:**

| ID | شدت | توضیح |
|----|------|-------|
| MUX-1 | 🔴 بحرانی | در حلقه ادغام، وقتی `writeVideo = true`، بعد از `muxer.writeSampleData`، `videoHasSample = readVideo()` فراخوان می‌شود ولی نتیجه `videoHasSample` **هیچ‌وقت بررسی نمی‌شود** — وقتی `readVideo()` false برگرداند (ویدیو تمام شد)، حلقه `while (!videoDone || !audioDone)` همچنان اجرا می‌شود و دوباره `writeVideo = true` ارزیابی می‌شود و `muxer.writeSampleData` با داده قدیمی فراخوان می‌شود — **داده تکراری در فایل خروجی!** |
| MUX-2 | 🟡 عملکردی | `readAudio()` وقتی `audioDone = true` ست می‌کند، ولی `audioHasSample` در حلقه اصلی آپدیت نمی‌شود بعد از فراخوان `readAudio()` — اگر آخرین نمونه صدا نوشته شود، حلقه ادامه می‌یابد چون `!audioDone` درست است. |
| MUX-3 | 🟡 عملکردی | وقتی `writeVideo = false` ولی `audioDone = true` (نمونه صدا وجود ندارد)، شرط `else` اجرا می‌شود و `muxer.writeSampleData` با `audioBuf` قدیمی فراخوان می‌شود — **داده صدا تکراری!** |
| MUX-4 | 🟠 زیبایی | `videoHasSample` و `audioHasSample` تعریف شده‌اند ولی در حلقه اصلی بررسی نمی‌شوند. |

## ✅ نقشه تعمیر

### فاز ۱: بحرانی 🔴
- [AAC-1] اضافه کردن مکانیزم بازآزمایی: وقتی اینکودر بوفری ندارد، PCM در بوففر موقت ذخیره شود و در تکرار بعدی دوباره ارسال شود
- [MUX-1+MUX-3] اصلاح حلقه ادغام: فقط وقتی نمونه معتبر وجود دارد بنویس
- [WAV-1] ریست کردن موقعیت بوففر قبل از خواندن هر بوفرد جدید دکودر

### فاز ۲: عملکردی 🟡
- [AAC-2+MP3-1] تغییر `lastPts` از `-1L` به `0L`
- [AAC-4] استفاده از مدیوزیشن برای پراگرس وقتی تریم صفر است
- [MP3-2] استفاده از `MediaUtil.findTrack`
- [MP3-3] افزودن بررسی `buf.remaining()`
- [WAV-2+WAV-3] حذف `extractor.advance()` اضافی وقتی EOS صف‌شده
- [WAV-4] استفاده از `maxOrNull() ?: 0f`
- [VID-2] اصلاح پاکسازی muxer در فینالی
- [VID-3] استفاده از تقسیم اعشاری برای فریم‌ریت

### فاز ۳: کیفیت 🔵
- [VID-4+VID-1] اصلاح ایندنت و ساختار بلوک try در videoPass
