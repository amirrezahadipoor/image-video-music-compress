# نقشهٔ مستندات

مخزن چند «نسل» سند دارد و تفاوتشان از اسم فایل معلوم نیست. این فایل می‌گوید
کدام سند **وضعیت امروز** است و کدام یکی **تاریخ** (برای مراجعه، نه برای عمل).

## اسناد زنده (اگر با کد تناقض داشتند، سند یا کد باگ است — هر دو را به‌روز کنید)

| سند | چه چیزی می‌گوید |
|---|---|
| [`../README.md`](../README.md) | معرفی، قابلیت‌ها، اینکه چه چیزی کشیده می‌شود و چه چیزی نه |
| [`KNOWN_ISSUES.md`](KNOWN_ISSUES.md) | مسائل باز و تصمیم‌های معلق؛ تنها سند «چه چیزی هنوز حل نشده» |
| [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md) | مجوز همهٔ وابستگی‌ها + تعهد LGPL |
| [`../SECURITY.md`](../SECURITY.md) | چطور گزارش امنیتی بدهید؛ روال چرخش کلید و پاک‌سازی تاریخچه |
| [`../CONTRIBUTING.md`](../CONTRIBUTING.md) | گیت‌های CI و قاعده‌های کد |
| [`BENCHMARK.md`](BENCHMARK.md) | چطور TTID/TTFD را درست اندازه بگیریم؛ چه عددی منتشرشدنی است |
| [`AUDIT_FIXES.md`](AUDIT_FIXES.md) | جدول «هر مورد بازبینی ← چه شد» |
| [`../CHANGELOG.md`](../CHANGELOG.md) | تغییرات هر نسخه |

## اسناد تاریخی (فقط زمینه، برای عمل به آن‌ها تکیه نکنید)

این فایل‌ها گزارش کار در دورهای گذشته‌اند. عددها و «رفع شد»هایشان مربوط به
همان تاریخ است و ممکن است با وضعیت امروز نخواند؛ صحت نهایی با کد و با
`KNOWN_ISSUES.md` سنجیده می‌شود.

- `ROUND*.md`، `*_REPORT.md`، `AUDIT_*.md` (اگر هستند) — گزارش‌های دورهای
- `fixes/` — پیش‌نویس‌های اصلاح

## قاعده

هیچ سندی «رفع شد» را بدون یک گیت اجراشدنی (تست/lint/script در `tools/`) اعلام
نکند: وضعیت رفعِ هر مورد باید یا در `AUDIT_FIXES.md` به یک گیت اشاره کند یا
صریحاً بگوید «نیازمند اقدام بیرونی است».
